## 我做的決定（請檢查）

- Q 主題分四組，照篩選版順序切，上一個／下一個的順序因此不變：Q1–Q4「系統怎麼架、撐不撐得住」、Q5–Q8「資料怎麼存、怎麼複製、怎麼拆」、Q9–Q11「同時發生時，誰先誰後」、Q12–Q16「資料在系統之間流動」。
- 英文組名要短，窄的目錄欄裡才不會折成兩行（2026-11-06 改，T 主題的四組一起縮短）：Spec requirements、Failures users see、Releases and change、Where data lives、Architecture and scale、Storing, copying, splitting、Concurrency and order、Data between systems。中文組名不變。
- 地圖說明不再提分區：「……用得到的段落，分組整理。」英文 “…that technical project managers (PMs) use, arranged in groups.”
- 目錄只列八個分組，不列主題，沒有收合（Debra 2026-11-06，設計稿 §5.2）。每一組開啟分組頁 `/<語言>/groups/<分組>/`（分組代號就是網址），右邊只有組名（`h1`）與它的主題卡；卡片元件 `TopicCard` 與地圖共用。分組在它有已上線主題時才有頁面，和主題、實驗一樣預先產生。分組頁標出自己（`aria-current="page"`），主題頁標出目前主題的分組，實驗頁標出它練習的主題的分組（`aria-current="true"`），都是粗體。目錄短了，原本把目錄欄捲到目前主題的程式拿掉；只有在寬螢幕又放大到 200% 字級時，目錄欄才需要捲動，這時標出的分組可能在捲動範圍外，頁面的 `h1` 仍說明讀者在哪裡（刻意接受）。
- 主題的段落改列在主題頁摘要下方的「本頁段落」／“In this topic”，編號清單，每一項連到該段。
