# data-systems-lab — working rules

Spec: `docs/2026-10-24-site-design.md`. Current plan: `docs/2026-10-24-phase-1-plan.md`. Process rules follow
`~/github/cpp-concurrency-lab/CLAUDE.md` (the same author's earlier lab), adapted below.

## Process

- Build one phase, and one lab, at a time; Debra reviews each before the next.
- Test-first: RED vitest, then implement; run `pnpm test && pnpm build && pnpm test:e2e` after every change.
- Verify visually: write a temporary `e2e/tmp-*.spec.ts` that screenshots into the session scratchpad, read
  the images, delete the spec. Screenshot both languages, at 375px and desktop width; check that the longer
  English text does not break the layout. Look for stranded sentences, split button rows, controls that look
  like bullets, identical-looking states, and identifiers that point at nothing on the page.
- Walk the page as a first-time reader before reporting; fix what you find instead of describing it.
- Do not commit unless Debra says "commit". Displayed SQL is sliced from `examples/*.sql` above
  `-- TEACHING-END`; never maintain a second copy. Never label a simulation as real execution.

## Content and languages

- Components contain no text, not even punctuation: every visible string, `aria-label`, `alt`, `title` and
  page title comes from `src/content/<lang>/` or `src/content/sections.ts` through the `Content` object.
- `src/content/sections.ts` is generated by `pnpm content`; never edit it by hand. The notes it reads live in
  `~/.claude/memories/` on Debra's machine only.
- Write `zh-TW` first, then `en`, in the same change. English terms and titles follow the book; see
  `docs/glossary.md`. In Chinese, write a term as 中文（English） the first time it appears in each section
  block or question, then Chinese only.
- Page numbers inside text are PDF-page tokens such as `{p:372}`; the screen shows printed pages (PDF − 24).
- Named placeholders (`{count}`) in interpolated strings; numbers through `Intl`.
- Internal links are base-absolute paths ending in `/`, never relative.
- Only live things are shown (`CURRENT_PHASE` in `src/config.ts`); no "coming soon" placeholders.

## Public-repo rules

- Write book content in our own words; quote only short phrases, with a page number.
- Never mention Debra's employer, clients or work systems, or scenarios taken from that work, anywhere:
  code, tests, comments, docs, commit messages.
- Commits use the repo-local GitHub noreply email. `.githooks/` (enabled with
  `git config core.hooksPath .githooks`) blocks banned words in staged content, paths, commit messages and
  author identity; the list lives outside the repo in `~/.claude/memories/data-systems-lab-banned-words.txt`.

## Learner-facing rules (from the cpp-concurrency-lab reviews)

- Every label explains itself; no codes such as "T3" or "Q7" on screen.
- Every disabled control says why and where to go, next to the control.
- Inputs look like inputs; the same state always has the same look.
- Never hide content the reader has earned.
- A deliberate non-change needs a caption saying why.
- One vocabulary across question, timeline, dry run and feedback, per language.
- Less prose, more structure. A diagram must earn its place: its caption says what it shows that the prose
  does not. In a lab it redraws when the reader acts. On a topic page, add a static sequence diagram
  (`SequenceDiagram`, data in the section's `diagram`) where the order of events across browser, server and
  database is the point and the text alone is hard to follow. If a table says it better, use the table.
